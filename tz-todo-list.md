# Техническое задание: веб-сайт «Список задач»

**Версия:** 1.3  
**Дата:** 09.11.2026  
**Тип продукта:** однопользовательское веб-приложение (MVP)  
**Статус:** черновик к согласованию  
**История изменений:** 1.1 — удалено представление «Календарь»; 1.2 — удалён поиск по содержимому; 1.3 — зафиксирована только светлая тема и добавлена цветовая палитра.

---

## 1. Общие сведения

### 1.1. Назначение

Простой веб-сайт для ведения личного списка задач. Задачи отображаются списком; их можно сортировать и фильтровать. Все данные хранятся в браузере пользователя и сохраняются после обновления страницы.

### 1.2. Цель

Дать пользователю лёгкий инструмент планирования без регистрации, сервера и сложной настройки: открыл страницу — добавил задачу — увидел её в списке.

### 1.3. Границы MVP

**Входит в объём:**

- создание, редактирование, выполнение и удаление задач;
- статусы «Новая», «В работе», «Готово»;
- срок с выбором даты в календаре и быстрыми пресетами;
- комментарии и вложения;
- корзина с восстановлением удалённых задач;
- настройка «запретить перевод в „Готово“ без результата»;
- иконка важности («огонь»);
- список задач;
- сортировка и фильтры;
- сохранение данных в браузере.

**Не входит в объём (см. раздел 13):** регистрация, синхронизация между устройствами, совместная работа, push-уведомления, повторяющиеся задачи, подзадачи, теги/проекты, отдельное представление «Календарь», поиск по содержимому.

### 1.4. Целевая аудитория

Один пользователь, который ведёт личные и рабочие задачи на одном устройстве. Ожидаемый объём данных — до 1 000 задач, до 10 файлов на задачу.

### 1.5. Термины

| Термин | Значение |
|---|---|
| Задача | Основная сущность: название, описание, срок, статус, результат и др. |
| Срок | Дата, к которой задача должна быть выполнена (без времени) |
| Пресет срока | Быстрая кнопка выбора даты: «Сегодня», «Завтра», «В конце месяца», «Без срока» |
| Результат | Текстовое описание итога работы; может быть обязательным при завершении |
| Важная задача | Задача с включённой иконкой «огонь» |
| Корзина | Список мягко удалённых задач с возможностью восстановления |
| Активная задача | Задача в статусе «Новая» или «В работе» |

## 2. Пользовательские сценарии

1. **Быстрое добавление.** Пользователь открывает сайт, нажимает «Новая задача», вводит название, оставляет срок «Сегодня» и сохраняет. Задача появляется в списке.
2. **Планирование на месяц.** Пользователь создаёт задачу и выбирает пресет «В конце месяца» — дата автоматически подставляется в поле срока.
3. **Работа над задачей.** Пользователь переводит задачу в «В работе», добавляет комментарий и прикрепляет файл.
4. **Завершение.** Пользователь ставит «Готово». Если включена настройка обязательного результата, приложение просит заполнить результат.
5. **Ошибка.** Пользователь случайно удалил задачу — восстанавливает её из корзины или через кнопку «Отменить» в уведомлении.

## 3. Стек и архитектура

### 3.1. Выбранный стек (максимально простой)

| Слой | Технология | Обоснование |
|---|---|---|
| Разметка | HTML5 | Без шаблонизаторов и сборки |
| Стили | CSS3 (переменные, Grid, Flexbox) | Без препроцессоров и UI-фреймворков |
| Логика | JavaScript ES2020+, нативный (vanilla) | Без React/Vue и зависимостей |
| Хранение задач | `localStorage` | Простейшее синхронное хранилище, переживает перезагрузку |
| Хранение файлов | `IndexedDB` (Blob) | `localStorage` не подходит для файлов из-за лимита ~5 МБ |
| Сборка | Отсутствует | Достаточно статической раздачи файлов |
| Backend | Отсутствует | Однопользовательский локальный режим |

**Требования к запуску:** любой статический веб-сервер (например, `python -m http.server 8000`) или хостинг статики. Открытие через `file://` не гарантируется из-за ограничений `IndexedDB`/`localStorage` в разных браузерах.

### 3.2. Структура проекта

```text
/
├── index.html          # единственная страница приложения
├── css/
│   └── styles.css      # все стили, адаптивность
├── js/
│   ├── app.js          # точка входа, состояние, обработчики
│   ├── storage.js      # localStorage + IndexedDB, миграции, ошибки
│   ├── ui.js           # рендер списка, карточек, модальных окон, тостов
│   └── utils.js        # даты, id, экранирование, форматирование
└── assets/
    └── icons.svg       # иконки (огонь, файл, комментарий, корзина и т.п.)
```

Допускается объединить модули в 2–3 файла, но разделение логики хранения и UI обязательно.

### 3.3. Архитектурные принципы

- **Единый источник состояния:** объект `state` в памяти, после каждого изменения — запись в хранилище и перерисовка затронутых частей UI.
- **Односторонний поток:** событие → изменение состояния → сохранение → рендер.
- **Без сетевых запросов:** приложение полностью работает офлайн, данные не покидают браузер.
- **Безопасный рендер:** пользовательский текст выводится через `textContent`/экранирование, не через небезопасный `innerHTML`.
- **Совместимость:** последние версии Chrome, Edge, Firefox, Safari; мобильные браузеры.

### 3.4. Альтернатива при необходимости синхронизации

Если позже потребуется доступ с нескольких устройств, допускается добавить минимальный backend: Node.js + Express + SQLite и загрузку файлов на диск. Это **не входит** в текущую версию и не влияет на MVP.

## 4. Модель данных

### 4.1. Задача (Task)

| Поле | Тип | Обязательное | Описание |
|---|---|---|---|
| `id` | string | да | UUID (`crypto.randomUUID()`), уникальный |
| `title` | string | да | Название, 1–120 символов после `trim` |
| `description` | string | нет | Описание, до 2 000 символов |
| `deadline` | string \| null | нет | Дата в формате `YYYY-MM-DD`, `null` — без срока |
| `status` | `"new"` \| `"in_progress"` \| `"done"` | да | Статус, по умолчанию `"new"` |
| `result` | string | нет | Результат, до 2 000 символов; обязателен при завершении, если включена настройка |
| `important` | boolean | да | Признак важности («огонь»), по умолчанию `false` |
| `comments` | Comment[] | да | Массив комментариев, по умолчанию `[]` |
| `attachments` | Attachment[] | да | Метаданные вложений, по умолчанию `[]` |
| `createdAt` | string | да | ISO 8601, момент создания |
| `updatedAt` | string | да | ISO 8601, момент последнего изменения |
| `completedAt` | string \| null | нет | Момент перевода в «Готово»; очищается при выходе из статуса |
| `deletedAt` | string \| null | нет | Момент мягкого удаления; `null` — задача не удалена |

### 4.2. Комментарий (Comment)

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | UUID |
| `text` | string | Текст, 1–1 000 символов |
| `createdAt` | string | ISO 8601 |

Комментарии отображаются в хронологическом порядке (старые сверху). Автор не хранится — приложение однопользовательское.

### 4.3. Вложение (Attachment)

| Поле | Тип | Описание |
|---|---|---|
| `id` | string | UUID, он же ключ записи в IndexedDB |
| `name` | string | Исходное имя файла |
| `type` | string | MIME-тип |
| `size` | number | Размер в байтах |
| `createdAt` | string | ISO 8601 |

Сам файл (Blob) хранится в IndexedDB в хранилище `files`:

```js
{ id, taskId, name, type, size, blob, createdAt }
```

### 4.4. Настройки (Settings)

```json
{
  "requireResultForDone": false
}
```

- `requireResultForDone` — запрет перевода задачи в «Готово» без непустого результата. По умолчанию `false` (выключено).

### 4.5. UI-состояние (не критично для данных)

Хранится отдельно и может быть сброшено без потери задач:

```json
{
  "sort": "deadline_asc"
}
```

### 4.6. Ключи хранилища

| Ключ | Содержимое |
|---|---|
| `todo.tasks.v1` | JSON-массив всех задач, включая мягко удалённые |
| `todo.settings.v1` | JSON-объект настроек |
| `todo.ui.v1` | JSON-объект UI-состояния |
| IndexedDB `todo-db`, store `files` | Блобы вложений |

### 4.7. Пример задачи

```json
{

  "title": "Подготовить отчёт за ноябрь",
  "description": "Свести показатели по продажам и отправить руководителю.",
  "deadline": "2026-11-30",
  "status": "in_progress",

  "comments": [
    {
      "id": "b2a1c3d4-1111-2222-3333-444455556666",

  "attachments": [
    {
```

## 5. Функциональные требования

### FR-01. Создание задачи

- Кнопка «Новая задача» доступна в шапке и в пустом состоянии списка.
- Форма создания открывается в модальном окне.
- Поля: «Название» (обязательное), «Описание», «Срок», «Статус», «Важность», «Результат», «Файлы».
- При открытии формы:
  - статус = «Новая»;
  - важность = выключена;
  - срок = **сегодня** (пресет «Сегодня» активен);
  - название получает фокус.
- Кнопки: «Сохранить» (основная), «Отмена».
- После сохранения задача появляется в списке согласно текущей сортировке, счётчики обновляются, показывается уведомление «Задача создана».
- `Enter` в поле «Название» сохраняет задачу; `Esc` закрывает форму с подтверждением, если есть несохранённые изменения.

### FR-02. Редактирование задачи

- Клик по карточке (кроме чекбокса, иконки огня и меню действий) открывает форму редактирования.
- Форма содержит те же поля, что и создание, плюс блок комментариев и список файлов.
- Изменения сохраняются по кнопке «Сохранить».
- При закрытии с несохранёнными изменениями — подтверждение «Закрыть без сохранения?».
- `updatedAt` обновляется при каждом сохранении.

### FR-03. Статусы

- Допустимые значения: «Новая», «В работе», «Готово».
- Статус можно изменить:
  - в форме задачи (выпадающий список);
  - на карточке через компактный селектор статуса;
  - чекбоксом завершения: установлен — «Готово», снят — «В работе».
- При переводе в «Готово» устанавливается `completedAt = now()`.
- При выходе из «Готово» `completedAt = null`.
- Если включена настройка `requireResultForDone` и результат пуст, перевод в «Готово» блокируется: открывается диалог «Укажите результат» с полем и кнопками «Сохранить и завершить» / «Отмена». Без результата завершение невозможно.
- Обратный перевод «Готово» → «В работе»/«Новая» разрешён всегда.
- Настройка не применяется задним числом: уже завершённые задачи без результата остаются «Готово».

### FR-04. Срок и пресеты

- Поле срока — нативный календарь `<input type="date">` с поддержкой ручного ввода.
- Над/рядом с календарём — кнопки быстрого выбора:
  - **«Сегодня»** — текущая локальная дата;
  - **«Завтра»** — текущая дата + 1 день;
  - **«В конце месяца»** — последний день текущего месяца;
  - **«Без срока»** — очищает дату (`deadline = null`).
- Активный пресет визуально выделен, если выбранная дата совпадает с его значением.
- В подсказке кнопки «В конце месяца» отображается конкретная дата (например, «30 ноября»).
- Допускается выбор прошедшей даты: задача сразу считается просроченной (с предупреждением в форме, но без блокировки).
- Время не задаётся; все сравнения выполняются по локальной дате пользователя.
- Отображение срока на карточке:
  - «Сегодня», «Завтра», «Просрочено на N дн.», «5 дек» (для текущего года), «5 дек 2027» (для другого года);
  - «Без срока» — нейтральный бейдж.
- Просроченная активная задача выделяется бейджем срока: текст `#D92D20` на фоне `#FDECEA`.

### FR-05. Важность («огонь»)

- На карточке и в форме есть переключатель-иконка огня.
- Включение/выключение на карточке применяется сразу, без открытия формы.
- Важная задача:
  - отображает заполненную иконку огня;
  - имеет доступный текст для скринридеров («Важная задача»);
  - учитывается в сортировке и фильтре «Только важные».
- Иконка не является единственным носителем смысла: в форме есть подпись «Важная задача».

### FR-06. Комментарии

- Блок комментариев доступен в форме редактирования задачи.
- Комментарий: текст 1–1 000 символов, кнопка «Добавить».
- После добавления комментарий сразу сохраняется, список обновляется, поле очищается.
- Отображаются текст и дата-время создания.
- Комментарий можно удалить с подтверждением.
- Пустой или состоящий из пробелов комментарий не добавляется.
- Счётчик комментариев показывается на карточке задачи.

### FR-07. Вложения

- Добавление файлов: кнопка «Прикрепить файл» и drag-and-drop в зону вложений.
- Ограничения:
  - до **10 файлов** на задачу;
  - до **10 МБ** на файл;
  - без ограничений по типу (кроме технических ограничений браузера).
- Файл сохраняется в IndexedDB; в задаче хранятся только метаданные.
- В списке вложений: имя, размер, иконка типа; для изображений (`image/*`) — миниатюра.
- Действия: скачать (через `URL.createObjectURL` + `<a download>`), удалить (с подтверждением).
- При превышении лимита — понятное сообщение, файл не добавляется.
- При удалении задачи в корзину файлы сохраняются; при окончательном удалении — удаляются из IndexedDB.
- Если файл в IndexedDB не найден, показывается «Файл недоступен» и кнопка удаления записи.
- Счётчик вложений показывается на карточке задачи.

### FR-08. Удаление и корзина

- Удаление задачи — мягкое: устанавливается `deletedAt`, задача исчезает из списка.
- После удаления показывается уведомление «Задача удалена» с кнопкой «Отменить» (доступна 5 секунд).
- Раздел «Корзина» доступен из шапки.
- В корзине отображаются удалённые задачи: название, дата удаления, срок, статус.
- Действия в корзине:
  - «Восстановить» — очищает `deletedAt`, задача возвращается в список;
  - «Удалить навсегда» — безвозвратно удаляет задачу, комментарии, метаданные и файлы из IndexedDB (с подтверждением);
  - «Очистить корзину» — удаляет все задачи безвозвратно (с подтверждением).
- Автоочистка: при запуске приложения задачи, удалённые более **30 дней** назад, удаляются безвозвратно.
- Пустая корзина показывает состояние «Корзина пуста».

### FR-09. Список задач

- Задачи отображаются единым списком.
- Каждая карточка содержит:
  - чекбокс завершения;
  - иконку огня (переключатель);
  - название;
  - бейдж статуса;
  - бейдж срока;
  - описание (обрезается до 2 строк, полностью видно в форме);
  - счётчики комментариев и вложений;
  - индикатор наличия результата;
  - меню действий: «Редактировать», «Удалить».
- Завершённые задачи отображаются приглушённо, название зачёркнуто.
- При любой сортировке, кроме «По статусу», завершённые задачи располагаются в конце списка.
- Пустое состояние: «Пока нет задач» + кнопка «Создать задачу».
- Если фильтры ничего не нашли: «Ничего не найдено» + кнопка «Сбросить фильтры».
- Счётчики над списком: всего, активных, просроченных, готовых.

### FR-10. Сортировка

Сортировка доступна в выпадающем списке панели инструментов и применяется в списке.

| Значение | Название | Правило |
|---|---|---|
| `deadline_asc` | Срок: сначала ближайшие | Дата по возрастанию; без срока — в конце |
| `deadline_desc` | Срок: сначала дальние | Дата по убыванию; без срока — в конце |
| `created_desc` | Новые сначала | `createdAt` по убыванию |
| `created_asc` | Старые сначала | `createdAt` по возрастанию |
| `title_asc` | По названию А–Я | Локальное сравнение, без учёта регистра |
| `status` | По статусу | Новая → В работе → Готово; внутри — срок по возрастанию |
| `important` | По важности | С огнём сверху; внутри — срок по возрастанию |

Правила:

- По умолчанию — `deadline_asc`.
- Задачи без срока всегда в конце соответствующей группы.
- Завершённые задачи в конце списка (кроме сортировки `status`).
- При равенстве ключей — сортировка по `createdAt` (новые сверху).
- Выбранная сортировка сохраняется в `localStorage` и восстанавливается после перезагрузки.

### FR-11. Фильтры

Фильтры располагаются в панели инструментов в виде раскрывающейся панели или набора чипов. Внутри группы действует логика «ИЛИ», между группами — «И».

| Группа | Значения | По умолчанию |
|---|---|---|
| Статус | Новая, В работе, Готово (мультивыбор) | Все |
| Важность | Все / Только важные | Все |
| Срок | Все, Просроченные, Сегодня, Завтра, На этой неделе, Без срока | Все |
| Вложения | Все / С файлами | Все |

Определения:

- **Просроченные:** `deadline < сегодня` и статус ≠ «Готово».
- **Сегодня / Завтра:** точное совпадение даты.
- **На этой неделе:** с сегодняшнего дня по воскресенье текущей недели включительно.
- **Без срока:** `deadline = null`.

Поведение:

- Активные фильтры отображаются чипами с возможностью удалить каждый.
- Кнопка «Сбросить фильтры» очищает все группы.
- Рядом показывается «Показано N из M».
- Фильтры не сохраняются между перезагрузками (сбрасываются), чтобы не скрывать задачи незаметно.

### FR-12. Настройки

- Кнопка-шестерёнка в шапке открывает модальное окно «Настройки».
- Переключатель **«Запретить перевод в „Готово“ без результата»**:
  - по умолчанию выключен;
  - сохраняется сразу в `localStorage`;
  - применяется к текущей сессии и после перезагрузки.
- Рядом — пояснение: «Если включено, при завершении задачи нужно заполнить поле „Результат“».
- Кнопка «Закрыть».
- Дополнительно (не обязательно): кнопка «Сбросить все данные» с двойным подтверждением. Если реализуется — удаляет задачи, настройки и файлы.

### FR-13. Сохранение данных

- Любое изменение (создание, редактирование, смена статуса, огонь, комментарий, вложение, удаление, восстановление, настройки) немедленно записывается в хранилище.
- После обновления страницы задачи, статусы, комментарии, вложения, настройки и выбранная сортировка восстанавливаются.
- Форма задачи сохраняется по кнопке «Сохранить»; промежуточный ввод в форму не сохраняется.
- При ошибке записи (переполнение квоты, запрет хранилища) показывается постоянный баннер: «Не удалось сохранить данные. Изменения могут быть потеряны после закрытия страницы». Приложение продолжает работать в памяти.
- При повреждении JSON в `localStorage`:
  - данные сохраняются в резервный ключ `todo.tasks.v1.corrupt.<timestamp>`;
  - приложение стартует с пустым списком и баннером «Данные повреждены, создана резервная копия».

## 6. Интерфейс и навигация

### 6.1. Структура страницы

```text
│                                                             │
│  Содержимое: список задач                                   │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 6.2. Карточка задачи (список)

```text
[✓] [🔥] Подготовить отчёт за ноябрь        [В работе] [30 ноя]
        Свести показатели по продажам…
        💬 2   📎 1   ✓ Результат есть          [⋯]
```

- Чекбокс — завершение; при включении фон `#2D7DFF`, галочка `#FFFFFF`.
- Огонь — важность; активная иконка `#FF7A00`, неактивная — контур `#9CA3AF`.
- Заголовок — `#1A1A2E`, описание — `#6B7280`; клик открывает задачу.
- Бейдж статуса — по схеме из раздела 6.4; бейдж срока: обычный — `#6B7280` на `#F0F2F5`, просроченный — `#D92D20` на `#FDECEA`.
- Меню «⋯»: «Редактировать», «Удалить»; иконка `#6B7280`, при наведении — `#2D7DFF`.

### 6.3. Модальное окно задачи

Порядок полей:

1. Название (input, обязательное).
2. Описание (textarea).
3. Срок: кнопки «Сегодня / Завтра / В конце месяца / Без срока» + календарь.
4. Статус (select).
5. Важность (тумблер с иконкой огня и подписью).
6. Результат (textarea; подсказка об обязательности).
7. Вложения (только после создания задачи либо с отложенным сохранением при создании).
8. Комментарии (только в режиме редактирования).
9. Кнопки «Сохранить» / «Отмена».

### 6.4. Визуальные требования

**Тема**

- Только светлая тема. Тёмная тема и переключатель тем не предусмотрены.
- Референс — `дизайн система.png` (в корне проекта). Из макета берутся: светло-серый фон, белые карточки с мягкой тенью, синие и зелёные акцентные блоки с белым текстом, синяя основная кнопка, скругления 12–16 px и воздушные отступы. CRM-контент и иллюстрации из макета не переносятся: для To-Do используются простые иконки.

**Базовая палитра**

  - «Новая» — индикатор `#9CA3AF`, фон `#F0F2F5`, текст `#6B7280`;
  - «В работе» — индикатор `#2D7DFF`, фон `#EAF2FF`, текст `#1A1A2E`;
  - «Готово» — индикатор `#00C853`, фон `#E8F8EE`, текст `#1A1A2E`.

- Завершённые задачи: название `#6B7280` с зачёркиванием, без сильного снижения контраста всей карточки.
- Тосты: успех — зелёный индикатор `#00C853`, ошибка — `#D92D20`, нейтральное сообщение — `#2D7DFF`; фон `#FFFFFF`, текст `#1A1A2E`.
- Иконки комментариев и вложений — `#6B7280`; при активном действии — `#2D7DFF`.
- Границы карточек, полей и разделители — `#E5E7EB`.

**Форма, тени и типографика**

- Радиус карточек и модальных окон — 12–16 px, кнопок — 8–10 px, бейджей — 999 px (pill).
- Тень карточек: `0 2px 8px rgba(26, 26, 46, 0.06)`; модальных окон: `0 16px 40px rgba(26, 26, 46, 0.16)`.
- Отступы кратны 4 px; шрифт системный (`system-ui`).
- Обычные карточки задач всегда белые; градиенты используются только на акцентных баннерах.
- Статус и важность не передаются только цветом: всегда есть текст, иконка или подпись.
- Контраст текста — не ниже WCAG 2.1 AA. Белый текст на `#2D7DFF` применять для заголовков, крупных надписей и кнопок; на зелёном фоне для мелкого текста использовать `#1A1A2E` или затемнять фон до `#007A33`.

**Адаптивность**

- ≥ 1024 px — широкий список с ограничением максимальной ширины контента;
- 600–1023 px — одноколоночная компоновка;
- < 600 px — карточки на всю ширину, панель фильтров в модальном/выдвижном виде, кнопки не меньше 44×44 px.

**Модальные окна**

- Закрываются по `Esc` и клику по подложке (с подтверждением при несохранённых изменениях).
- Фокус удерживается внутри модального окна; после закрытия возвращается на вызвавший элемент.

### 6.5. Уведомления (тосты)

- «Задача создана», «Изменения сохранены», «Задача удалена» + «Отменить», «Задача восстановлена», «Файл слишком большой», «Не удалось сохранить данные».
- Длительность — 4–5 секунд, кроме ошибок хранения (постоянный баннер).
- Тосты не перекрывают основные действия и закрываются кнопкой.
- Цветовые индикаторы тостов — по разделу 6.4: успех `#00C853`, ошибка `#D92D20`, нейтральное сообщение `#2D7DFF`.

## 7. Валидация и обработка ошибок

| Ситуация | Поведение |
|---|---|
| Пустое название | Подсветка поля, сообщение «Введите название задачи», сохранение блокируется |
| Название > 120 символов | Счётчик/ограничение `maxlength`, сообщение |
| Описание/результат > 2 000 символов | `maxlength`, сообщение |
| Комментарий пустой | Кнопка «Добавить» неактивна или сообщение |
| Комментарий > 1 000 символов | `maxlength`, сообщение |
| Некорректная дата | Сообщение «Укажите корректную дату», сохранение блокируется |
| Прошедшая дата | Предупреждение, но сохранение разрешено |
| Завершение без результата при включённой настройке | Диалог ввода результата, статус не меняется до заполнения |
| Файл > 10 МБ | Сообщение «Файл больше 10 МБ», файл не добавляется |
| Больше 10 файлов | Сообщение «Можно прикрепить не более 10 файлов» |
| Ошибка IndexedDB | Сообщение, метаданные не сохраняются, задача остаётся без файла |
| Переполнение localStorage | Постоянный баннер, работа в памяти |
| Повреждённые данные | Резервная копия + пустой старт + баннер |
| Нет доступа к хранилищу (приватный режим) | Баннер «Данные не сохраняются в этом режиме» |

Все сообщения — на русском языке, без технических кодов в основном тексте.

## 8. Нефункциональные требования

### 8.1. Производительность

- Первый рендер при 1 000 задачах — не более 300 мс на среднем ноутбуке.
- Фильтрация 1 000 задач — не более 100 мс.
- Изменение статуса/огня — визуальный отклик не более 50 мс.
- Файлы не загружаются в память списка; миниатюры создаются только для изображений и только при необходимости.

### 8.2. Надёжность

- Все записи в `localStorage` — атомарно по ключу (сериализация всего массива).
- Ошибки `JSON.parse` и `IndexedDB` перехватываются, приложение не «падает».
- При закрытии вкладки во время сохранения файла — файл либо сохранён полностью, либо не отображается; «битые» записи удаляются при следующем старте.

### 8.3. Безопасность и приватность

- Нет сетевых запросов и аналитики.
- Нет регистрации и передачи данных третьим лицам.
- Пользовательский текст экранируется; загруженные файлы не исполняются в приложении.
- Скачивание файлов — только по явному действию пользователя.

### 8.4. Совместимость

- Chrome, Edge, Firefox, Safari — последние две мажорные версии.
- Мобильные Safari и Chrome.
- Разрешения: 360×640 — 1920×1080.
- Не поддерживается IE11.

### 8.5. Доступность

- Семантические элементы (`button`, `label`, `dialog`/`role="dialog"`).
- Все иконки-кнопки имеют `aria-label`.
- Управление с клавиатуры: `Tab`, `Enter`, `Esc`, `Space` для чекбоксов.
- Видимый фокус.
- Статусы и важность дублируются текстом/подписью, не только цветом.
- Контраст WCAG 2.1 AA.

### 8.6. Локализация

- Интерфейс на русском языке.
- Даты — `ru-RU` (день месяц, месяц в родительном падеже).
- Начало недели — понедельник (используется в фильтре «На этой неделе»).
- Часовой пояс — локальный пояс браузера.

## 11. Ограничения и риски

| Риск / ограничение | Влияние | Меры |
|---|---|---|
| Очистка данных браузера удаляет задачи | Потеря всех данных | Предупреждение в настройках; в v1.1 — экспорт/импорт JSON |
| Лимит `localStorage` ~5 МБ | Много задач/длинных текстов | Хранить только текст; рекомендация до 1 000 задач |
| Лимит IndexedDB и квоты браузера | Нельзя прикрепить файлы | Проверка размера, сообщение, предупреждение при заполнении квоты |
| Данные привязаны к origin | Перенос сайта = потеря данных | Не менять домен; в v1.1 — экспорт |
| Нет синхронизации | Один пользователь — одно устройство | Заявлено в границах MVP |
| Часовой пояс и переход на летнее время | Сдвиг «сегодня» | Сравнивать локальные даты через `YYYY-MM-DD` без UTC-времени |
| Приватный режим браузера | Данные не сохраняются | Баннер-предупреждение |
| Большие файлы нагружают память | Зависание при скачивании | Не читать файлы в память списка; `createObjectURL` по требованию |

## 13. Что не входит в MVP ( backlog )

- Регистрация, авторизация, синхронизация между устройствами.
- Совместная работа и назначение задач.
- Push/email-уведомления и напоминания.
- Повторяющиеся задачи.
- Подзадачи, чек-листы внутри задачи.
- Теги, проекты, папки.
- Отдельное представление «Календарь»: в MVP задачи отображаются только списком.
- Поиск по содержимому (названию, описанию, комментариям и именам файлов).
- Ручной порядок задач перетаскиванием.
- Экспорт/импорт JSON и резервное копирование (приоритет v1.1).
- Тёмная тема и переключатель тем — не предусмотрены, интерфейс только светлый.
- Офлайн-режим через Service Worker (приложение и так работает без сети после загрузки).
- Редактирование комментариев (в MVP — добавление и удаление).
